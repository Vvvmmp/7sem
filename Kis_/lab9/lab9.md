## **Лабораторная работа № 9**

## **Специальный язык запросов**

**Цель:** получить навык создания отчетов с написанием запросов на специальном языке запросов в среде «1С-Предприятие 8».

**Теоретические сведения**

Язык запросов в системе «1С:Предприятие 8» является одним из основных инструментов для получения данных из информационной базы. Запросы дают возможность выбирать большие объёмы информации, фильтровать, сортировать и группировать их, а также соединять данные из разных источников — справочников, документов, регистров сведений и регистров накопления. Фактически любой отчёт в 1С, за исключением самых простых, строится на основе запроса, который извлекает из базы данных именно те сведения, которые нужны пользователю, и в том виде, в котором их удобно анализировать. Запросы могут использоваться не только в отчётах, но и в обработках, в модулях документов для формирования движений, а также в любых алгоритмических местах конфигурации, где требуется сложная выборка данных.

Основные конструкции языка запросов 1С записываются на русском языке. К базовым операторам относятся:

|  |  |
| --- | --- |
| Оператор | Описание |
| ВЫБРАТЬ | Начало запроса, перечисление полей для выборки |
| ИЗ | Указывает источник данных (таблицу) |
| КАК | Задаёт псевдоним (алиас) для поля или таблицы |
| ГДЕ | Условие отбора записей (фильтрация) |
| СГРУППИРОВАТЬ ПО | Группировка записей для агрегации |
| УПОРЯДОЧИТЬ ПО | Сортировка результата |
| ИТОГИ ПО | Подведение итогов по группировкам |
| ОБЪЕДИНИТЬ | Объединение результатов двух запросов |

Агрегатные функции:

|  |  |
| --- | --- |
| Функция | Описание |
| СУММА(...) | Вычисляет сумму значений поля |
| КОЛИЧЕСТВО(...) | Подсчитывает количество записей |
| МАКСИМУМ(...) | Находит максимальное значение |
| МИНИМУМ(...) | Находит минимальное значение |
| СРЕДНЕЕ(...) | Вычисляет среднее арифметическое |

Типы соединений таблиц:

|  |  |
| --- | --- |
| Оператор | Описание |
| ВНУТРЕННЕЕ СОЕДИНЕНИЕ | Возвращает только записи, присутствующие в обеих таблицах |
| ЛЕВОЕ СОЕДИНЕНИЕ | Все записи из левой таблицы + совпадающие из правой (NULL если нет совпадения) |
| ПРАВОЕ СОЕДИНЕНИЕ | Все записи из правой таблицы + совпадающие из левой |
| ПОЛНОЕ СОЕДИНЕНИЕ | Все записи из обеих таблиц (где есть совпадение — соединяет, где нет — NULL) |

Условные конструкции:

|  |  |
| --- | --- |
| Оператор | Описание |
| ВЫБОР КОГДА ... ТО ... ИНАЧЕ ... КОНЕЦ | Условный оператор внутри запроса |
| ЕСТЬ NULL | Проверка на неопределённое значение |
| В () | Проверка вхождения в список значений |
| МЕЖДУ ... И ... | Проверка попадания в диапазон (включая границы) |
| ПОХОЖЕ | Сравнение по шаблону (с символами %, \_) |

Работа с датами:

|  |  |
| --- | --- |
| Оператор | Описание |
| ДОБАВИТЬКДАТЕ | Прибавляет интервал к дате (год, месяц, день, час и т.д.) |
| РАЗНОСТЬДАТ | Вычисляет разницу между датами в заданных единицах |
| НАЧАЛОПЕРИОДА | Возвращает начало периода (дня, месяца, квартала, года) |
| КОНЕЦПЕРИОДА | Возвращает конец периода |
| ГОД, КВАРТАЛ, МЕСЯЦ, ДЕНЬ, ЧАС, МИНУТА, СЕКУНДА | Извлекают соответствующую часть из даты |

Специальные операторы:

|  |  |
| --- | --- |
| Оператор | Описание |
| ССЫЛКА | Проверяет, является ли значение ссылкой на указанный тип |
| РАЗРЕШЕННЫЕ | Учитывает права доступа при выборке |
| ПЕРВЫЕ ... | Ограничивает количество записей |
| ИНДЕКСИРОВАТЬ | Рекомендация оптимизатору использовать индекс |
| ВЫРАЗИТЬ(... КАК Тип) | Приводит значение к указанному типу |

Запрос в 1С по своему синтаксису напоминает классический SQL, однако имеет ряд особенностей, обусловленных объектной моделью платформы. В запросе можно обращаться не к реальным таблицам базы данных, а к метаданным конфигурации – справочникам, документам, регистрам. Платформа самостоятельно транслирует такие обращения в физические таблицы. Кроме того, в языке запросов 1С доступны виртуальные таблицы, которые не хранятся в базе данных, а вычисляются системой на лету.

Например, запрос, где требуется выявить дефицитные товары, будет выглядеть следующим образом:

|  |
| --- |
| ВЫБРАТЬ  ОстаткиОстатки.Номенклатура КАК Номенклатура,  ОстаткиОстатки.Склад КАК Склад,  ОстаткиОстатки.КоличествоОстаток КАК Количество  ИЗ  РегистрНакопления.Остатки.Остатки(, ) КАК ОстаткиО  ГДЕ  ОстаткиО.КоличествоОстаток <= 0 |

При работе с запросами в системе компоновки данных важно понимать, что текст запроса не обязательно писать вручную. Платформа предоставляет мощный визуальный конструктор запросов, в котором можно выбирать таблицы, поля, задавать условия и связи между таблицами, а система сама сгенерирует корректный текст. Конструктор запросов доступен при редактировании набора данных типа «Запрос» в схеме компоновки данных.

<u>Задание 2.</u>

Пусть на модельном промышленном предприятии продукция хранится на различных складах. На предприятии ведётся планирование произведённого и отгруженного товара. Цены на продаваемую продукцию устанавливаются отделом продаж. У менеджеров по продажам должна быть возможность по запросу предоставлять список доступных для отгрузки товаров и цену на каждую позицию номенклатуры:

* Перечень производимой продукции должен храниться в справочнике «Номенклатура»
* Список складов должен быть представлен в справочнике «Склады»
* Планируемые поступления товаров оформляются на конкретный склад: перечень товаров содержит наименование номенклатуры и количество поступившей продукции.
* Планируемые отгрузки товаров оформляются с разных складов: перечень товаров включает в себя наименование номенклатуры, количество отгружаемой продукции и склад, с которого происходит отгрузка.
* Цены товаров устанавливаются перечнем не чаще одного раза в сутки на конкретные позиции номенклатуры.

Регистр накопления остатков должен фиксировать остатки различной продукции на каждом складе

Регистр сведений должен хранить историю изменения цены на различные позиции производимой продукции

На основе имеющихся данных необходимо составить отчёты:

* Прайс-лист товаров с общим количеством на всех складах
* Список дефицитных товаров на складах (считать позицию на конкретном складе дефицитной, если остатки по плану меньше или равны 0)
* \* Список товаров, на которые не установлена цена, либо которые оказались вне учёта (считать позицию вне учёта, если на неё нет ни поступлений, ни отгрузок)

*Подсказки:*

* Все варианты отчёта составляются в виде списка
* Прайс-лист должен включать в себя наименование, цену и количество. Следует воспользоваться группировкой по наименованию при формировании варианта отчёта: не забудьте указать количество в качестве ресурса отчёта
* Дефицитными так же считаются товары, которые оказались вне учёта (то есть отсутствуют записи о них в регистре остатков)
* Для составления списка товаров с неустановленной ценой или оказавшихся вне учёта потребуется «ПОЛНОЕ СОЕДИНЕНИЕ»
