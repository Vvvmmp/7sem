## Ответы на вопросы

**1. Чем Hive отличается от SQFLite? Когда что выбирать?**
Hive — NoSQL-хранилище «ключ → значение» на чистом Dart, быстрое, с шифрованием, без SQL. SQFLite — реляционная SQLite с таблицами, `JOIN`, индексами и транзакциями. Hive выбирают для настроек, кеша, небольших наборов объектов; SQFLite — для связанных данных и сложных запросов/фильтров.

**2. Как Hive обеспечивает типобезопасность?**
Через типизированные боксы `Box<PostItem>` (в них нельзя положить другой тип) и адаптеры, которые читают и пишут поля строго определённых типов.

**3. Что такое адаптер в Hive и зачем он нужен?**
`TypeAdapter` объясняет Hive, как превратить объект в байты и обратно. Он нужен для любых своих классов. У каждого адаптера свой уникальный `typeId`, его нужно зарегистрировать через `Hive.registerAdapter` до открытия бокса.

**4. Как работает шифрование в Hive? Где хранится ключ?**
Hive шифрует значения алгоритмом AES-256 (`HiveAesCipher`) с 32-байтным ключом. Сам ключ Hive не хранит — его нужно хранить самому, в защищённом хранилище ОС (`flutter_secure_storage`). Потерянный ключ = недоступные данные.

**5. Как сжатие влияет на производительность и размер?**
Размер файла уменьшается (удаляются старые версии записей и «дыры» после удалений). Сама операция читает и переписывает весь файл, поэтому на больших боксах она заметна по времени, и её не стоит вызывать часто. После сжатия последующее открытие бокса быстрее, так как файл короче.

**6. Что такое compactionStrategy в Hive?**
Параметр `openBox`: функция `(entries, deletedEntries) → bool`, решающая, пора ли сжимать бокс автоматически. По умолчанию сжатие запускается, когда удалённых записей больше 60 и их доля от всех записей больше 15%.

**7. Как Hive работает с изолятами?**
Бокс — объект одного изолята: другой изолят не видит его кэш. Из второго изолята нужно открывать бокс заново, а одновременная запись в один файл из двух изолятов может его повредить. Hive 2 для этого не предназначен (в новых версиях `IsolatedHive` решает проблему).

**8. Как мигрировать данные при изменении схемы?**
Hive миграций не имеет. Адаптеры, созданные генератором, хранят поля по номерам (`@HiveField(n)`): новые поля добавляют с новым номером и значением по умолчанию, старые номера не меняют и не переиспользуют. В моём адаптере поля читаются по порядку, поэтому менять его без очистки/конвертации бокса нельзя. Для серьёзных изменений: прочитать старые данные, преобразовать и записать в новый бокс.

**9. Чем Hive.openBox() отличается от Hive.openLazyBox()? Когда что использовать?**
`openBox` сразу загружает все значения в память — чтение мгновенное, но для больших данных это дорого. `openLazyBox` держит в памяти только ключи, значения читаются с диска по запросу (`await box.get`). Обычный бокс — для небольших данных, lazy — для больших (крупные списки, много записей).

**10. Как хранить список объектов в Hive? Какие ограничения?**
Либо `box.add` каждого объекта отдельной записью, либо `List<PostItem>` как значение одной записи (адаптер для элемента должен быть зарегистрирован). Ограничения: список вытаскивается из бокса целиком, при изменении нужно записывать его заново; элементы должны быть поддерживаемых типов или иметь адаптер; поиска/фильтров по элементам нет — только перебор.

**11. Что произойдёт, если не закрыть box перед завершением приложения?**
Данные не потеряются: записи сразу дописываются в файл. Но без `close()` не освобождаются ресурсы и файл блокировки. Обычно бокс держат открытым всё время работы и закрывают в `dispose` или при выходе, если он больше не нужен.

**12. Как удалить все данные из box? Чем box.clear() отличается от box.deleteFromDisk()?**
`box.clear()` удаляет все записи, но бокс остаётся открытым и пригодным к использованию (файл сохраняется). `box.deleteFromDisk()` закрывает бокс и удаляет его файл целиком — дальше его нужно открывать заново.

**13. Как реализовать поиск и сортировку данных в Hive? Сравните с SQFLite.**
Запросов в Hive нет: берём `box.values` и применяем `where(...)` и `sort(...)` на Dart (как `keys.where(...)` в [hive_screen.dart:48](lib/screens/hive_screen.dart#L48)). Всё происходит в памяти, поэтому подходит для небольших данных. В SQFLite поиск и сортировка делаются SQL (`WHERE ... LIKE`, `ORDER BY`) с индексами, и они эффективнее на больших объёмах.

**14. Как ограничить доступ к CRUD-операциям в зависимости от роли пользователя?**
Проверять роль перед операцией и не показывать недоступные элементы: у меня `isAdmin` определяет, строятся ли `+`, ✎ и 🗑 ([hive_screen.dart:68](lib/screens/hive_screen.dart#L68), [hive_screen.dart:82](lib/screens/hive_screen.dart#L82)). Это защита на уровне интерфейса; Hive сам прав доступа не имеет, для надёжности проверку добавляют и в слой данных.

**15. Как связать избранное с конкретным пользователем? Приведите структуру данных.**
Бокс `favorites`, где ключ — идентификатор пользователя, значение — список ключей постов:
```
favorites = { 'Admin': [0, 3], 'Anna': [1] }
```
Альтернатива — отдельные записи вида `{userId, postId}`.

**16. Какие данные нельзя хранить в Hive? Приведите примеры.**
Нельзя без адаптера — свои классы; нельзя — объекты, которые не превращаются в байты: `Widget`, `BuildContext`, `Function`, открытые соединения, `File` (хранят путь). Не стоит — большие файлы и картинки (хранят путь), сложные реляционные данные, а ключи и пароли без шифрования (нужен `HiveAesCipher`).

**17. Как Hive работает с асинхронностью? Нужно ли использовать изоляты?**
Открытие бокса, `put`, `delete`, `compact` асинхронны (возвращают `Future`); чтение из обычного бокса синхронно, так как данные в памяти. Изоляты для Hive не нужны: записи быстрые, файловый ввод-вывод не блокирует UI. Изоляты имеют смысл лишь для очень тяжёлой обработки данных.
