# Лабораторная работа №3 — простейший JSON-RPC-сервис

## Что есть в проекте

| Папка / файл | Что это |
|---|---|
| `JSONRPCServer/` | сервер на ASP.NET Core, реализует JSON-RPC 2.0 |
| `GoClient/` | клиент на Go, демонстрирует все вызовы |
| `http/jsonrpc.http` | готовые запросы для REST Client (VS Code) |

## Как запустить

```bash
# 1. Сервер (слушает http://localhost:5000)
cd JSONRPCServer
dotnet run

# 2. В другом терминале — клиент на Go
cd GoClient
go run .                                  # по умолчанию http://localhost:5000/jsonrpc
go run . http://localhost:5000/jsonrpc    # или явно указать адрес
```

Для ручной проверки откройте `http/jsonrpc.http` в VS Code с расширением **REST Client** и нажимайте `Send Request` над нужным запросом.

## Что такое JSON-RPC (коротко)

JSON-RPC — протокол удалённого вызова процедур. В отличие от REST, здесь нет ресурсов и разных HTTP-методов: **все вызовы идут одним `POST` на один адрес** (`/jsonrpc`). Имя процедуры и аргументы передаются в теле.

**Запрос:**

```json
{ "jsonrpc": "2.0", "method": "SUM", "params": [3, 4], "id": 1 }
```

| Поле | Значение |
|---|---|
| `jsonrpc` | версия протокола, всегда `"2.0"` |
| `method` | имя процедуры |
| `params` | аргументы: массив (позиционно) или объект (по именам) |
| `id` | номер запроса; сервер вернёт его в ответе, чтобы клиент сопоставил ответ с запросом |

**Успешный ответ:**

```json
{ "jsonrpc": "2.0", "result": 7, "id": 1 }
```

**Ответ с ошибкой** (вместо `result` поле `error`):

```json
{ "jsonrpc": "2.0", "error": { "code": -32000, "message": "Division by zero" }, "id": 9 }
```

**Уведомление** — запрос **без поля `id`**. Сервер выполняет процедуру, но ничего не отвечает (HTTP `204 No Content`).

## Процедуры

| Сигнатура | Результат | Ошибки |
|---|---|---|
| `double SUM(double x, double y)` | `x + y` | — |
| `double SUB(double x, double y)` | `x - y` | — |
| `double MUL(double x, double y)` | `x * y` | — |
| `double DIV(double x, double y)` | `x / y` | `y = 0` → `-32000 Division by zero` |
| `int FACT(int x)` | `x!` | результат больше `int.MaxValue` (т.е. `x ≥ 13`) → `-32001 Result exceeds int range`; `x < 0` → `-32602` |

Имя метода регистронезависимо (`SUM`, `sum`, `Sum` — одно и то же).

### Позиционные и именованные параметры

Оба способа дают один и тот же результат:

```json
{ "jsonrpc": "2.0", "method": "SUB", "params": [3, 10],           "id": 1 }
{ "jsonrpc": "2.0", "method": "SUB", "params": {"y": 10, "x": 3}, "id": 2 }
```

Оба вернут `-7`. В именованной форме порядок ключей не важен, важны имена `x` и `y`.

## Пакетная обработка (batch)

Клиент может отправить **массив** запросов одним HTTP-запросом. Сервер выполнит каждый и вернёт **массив** ответов:

```json
[
  { "jsonrpc": "2.0", "method": "SUM",  "params": [1, 2], "id": 1 },
  { "jsonrpc": "2.0", "method": "DIV",  "params": [1, 0], "id": 2 },
  { "jsonrpc": "2.0", "method": "SUB",  "params": [9, 9] }
]
```

```json
[
  { "jsonrpc": "2.0", "result": 3, "id": 1 },
  { "jsonrpc": "2.0", "error": { "code": -32000, "message": "Division by zero" }, "id": 2 }
]
```

Правила:
- ошибка в одном запросе **не ломает** остальные: каждый получает свой ответ;
- на уведомления (без `id`) ответов в массиве нет;
- если в пакете только уведомления, сервер возвращает `204` без тела;
- пустой массив `[]` — это ошибка `-32600 Invalid Request` (один объект, не массив).

## Коды ошибок

| Код | Сообщение | Когда |
|---|---|---|
| `-32700` | Parse error | тело — не JSON |
| `-32600` | Invalid Request | нет `"jsonrpc": "2.0"`, `method` не строка, запрос не объект, пустой batch |
| `-32601` | Method not found | нет такой процедуры |
| `-32602` | Invalid params | не то число параметров, лишний/отсутствующий параметр, не число, дробное для `FACT`, отрицательное для `FACT` |
| `-32603` | Internal error | непредвиденное исключение на сервере |
| `-32000` | Division by zero | `DIV` с `y = 0` |
| `-32001` | Result exceeds int range | `FACT` переполнил `int` |

Коды `-32700…-32603` определены спецификацией JSON-RPC 2.0. Диапазон `-32000…-32099` спецификация отдаёт под ошибки сервера, поэтому ошибки из задания получили коды оттуда. В поле `data` сервер пишет подробности, например `"13! > 2147483647"`.

## Объяснение кода сервера

Сервер разбит на три файла.

### `Program.cs` — HTTP-слой

```csharp
app.MapPost("/jsonrpc", async (HttpRequest request) =>
{
    var body = await reader.ReadToEndAsync();
    JsonNode? response = JsonRpcHandler.Handle(body);
    return response is null
        ? Results.NoContent()
        : Results.Content(response.ToJsonString(jsonOptions), "application/json");
});
```

Один эндпоинт: читает тело запроса строкой и отдаёт его в `JsonRpcHandler`. Если тот вернул `null` (пришли только уведомления), отвечаем `204`, иначе отдаём JSON.

Тело читается строкой, а не через `[FromBody]`-модель, потому что запрос бывает и объектом, и массивом. К тому же битый JSON надо превратить в ответ `-32700`, а не в стандартную ошибку `400` от ASP.NET.

### `JsonRpcHandler.cs` — протокол JSON-RPC

**Таблица методов.** Каждой процедуре сопоставлены имена её параметров и функция-обёртка:

```csharp
["DIV"]  = (["x", "y"], a => Procedures.Div(ToDouble(a[0], "x"), ToDouble(a[1], "y"))),
["FACT"] = (["x"],      a => Procedures.Fact(ToInt(a[0], "x"))),
```

Список имён (`["x", "y"]`) позволяет единообразно поддержать обе формы `params`: их приводят к массиву в порядке объявления, и дальше обёртка работает только с массивом.

**`Handle(body)`** — точка входа:
1. `JsonNode.Parse`; при `JsonException` возвращается `-32700 Parse error`.
2. Если корень — `JsonArray`, это batch. Каждый элемент обрабатывается через `HandleSingle`, ненулевые ответы собираются в массив. Пустой массив даёт ошибку, массив без ответов — `null`.
3. Иначе вызывается `HandleSingle` для одного объекта.

**`HandleSingle(node)`** — один запрос:
1. Проверяет, что это объект, а `id` — строка, число или `null`.
2. Признак уведомления: `!req.ContainsKey("id")`. Важно, что проверяется именно **отсутствие поля**: `"id": null` — это обычный запрос, на него ответ есть.
3. Проверяет `jsonrpc == "2.0"` и что `method` — строка.
4. Находит метод в таблице (иначе `-32601`).
5. `BindParams` превращает `params` в массив аргументов.
6. Вызывает процедуру и собирает `{"jsonrpc","result","id"}`.

Любая ошибка — это `JsonRpcException(code, message, data)`, которую ловит `catch` и превращает в объект `error`. Остальные исключения дают `-32603 Internal error`. Для уведомлений ответ не формируется, даже если произошла ошибка.

**`BindParams(params, names)`** — привязка параметров:
- `JsonArray` — проверяется длина, массив возвращается как есть (позиционно);
- `JsonObject` — сначала проверяется, что нет лишних ключей, затем для каждого имени из `names` берётся значение (порядок задаёт `names`, а не JSON);
- что-то другое — `-32600`.

**`ToDouble` / `ToInt`** — проверяют, что значение является JSON-числом (строка `"1"` не подойдёт). `ToInt` дополнительно не пропускает дробные числа: `TryGetValue<int>` для `2.5` вернёт `false`.

### `Procedures.cs` — сами процедуры

Обычные C#-методы, которые ничего не знают о JSON:

```csharp
public static double Div(double x, double y) =>
    y == 0 ? throw new JsonRpcException(DivisionByZero, "Division by zero") : x / y;
```

Деление на ноль приходится проверять вручную: для `double` C# не бросает исключение, а возвращает `Infinity`.

```csharp
for (int i = 2; i <= x; i++)
    result = checked(result * i);
```

`checked` включает контроль переполнения. Без него `13!` молча «перевалил» бы через `int.MaxValue` и дал бы мусор (`1932053504`). С ним бросается `OverflowException`, и мы превращаем его в ошибку `-32001`. Максимум для `int` — `12! = 479001600`.

## Объяснение кода клиента (`GoClient/main.go`)

Используется только стандартная библиотека: `net/http` и `encoding/json`.

**Структуры** повторяют формат протокола:

```go
type Request struct {
    JSONRPC string `json:"jsonrpc"`
    Method  string `json:"method"`
    Params  any    `json:"params,omitempty"`
    ID      *int   `json:"id,omitempty"`
}
```

- `Params any` позволяет передать и срез `[]any{3, 4}` (позиционно), и `map[string]any{"x": 3}` (по именам): `encoding/json` превратит их в массив или объект.
- `ID *int` с `omitempty`: если указатель `nil`, поле `id` вообще не попадёт в JSON. Так клиент и шлёт **уведомления**.

**Методы клиента:**
- `Call(method, params)` — одиночный вызов. Сам выдаёт следующий `id`, отправляет запрос и разбирает ответ в `Response`.
- `Notify(method, params)` — уведомление без `id`; клиент ждёт `204` без тела.
- `Batch([]Request)` — шлёт массив запросов и разбирает массив ответов.
- `post(body)` — общая отправка: сериализует тело, печатает `-->` (что ушло) и `<--` (что пришло).

В `Response` поле `Result` имеет тип `json.RawMessage`: результат может быть и `double`, и `int`, поэтому клиент печатает его как есть.

**`main()`** по очереди демонстрирует:
1. каждую процедуру в позиционной и именованной форме;
2. ошибки из задания: деление на ноль, `FACT(13)`;
3. ошибки протокола: неизвестный метод, неверное число параметров;
4. уведомление;
5. пакетный вызов: 5 запросов и 1 уведомление; в ответе 5 элементов, среди них две ошибки.

Пример вывода:

```
=== DIV на ноль -> ошибка ===
--> {"jsonrpc":"2.0","method":"DIV","params":[5,0],"id":9}
<-- {"jsonrpc":"2.0","error":{"code":-32000,"message":"Division by zero"},"id":9}
    id=9 ОШИБКА -32000: Division by zero

=== Пакетный вызов (batch): 5 запросов + 1 уведомление одним HTTP-запросом ===
--> [{"jsonrpc":"2.0","method":"SUM","params":[1,2],"id":15}, ... ]
<-- [{"jsonrpc":"2.0","result":3,"id":15},{"jsonrpc":"2.0","result":12,"id":16}, ... ]
    id=15 РЕЗУЛЬТАТ: 3
    id=16 РЕЗУЛЬТАТ: 12
    id=17 ОШИБКА -32000: Division by zero
    id=18 РЕЗУЛЬТАТ: 3628800
    id=19 ОШИБКА -32001: Result exceeds int range (20! > 2147483647)
```

## Тесты (`http/jsonrpc.http`)

Файл разбит на 5 блоков:
1. все процедуры с позиционными параметрами;
2. все процедуры с именованными параметрами;
3. ошибки из задания (`DIV` на 0, `FACT(13)`);
4. ошибки протокола (`-32700`, `-32600`, `-32601`, `-32602`) и уведомление;
5. batch: смешанный пакет, пакет с мусорными элементами, пустой пакет, пакет только из уведомлений.

В заголовке каждого запроса указан ожидаемый результат.
